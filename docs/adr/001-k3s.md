# ADR-001 — Use k3s over full Kubernetes

**Date:** 2026-03-24
**Status:** Decided

## Context

The cluster runs on two Raspberry Pis (Pi 5 + Pi 4). Full Kubernetes (kubeadm) is resource-heavy — the control plane components alone (etcd, kube-apiserver, kube-controller-manager, kube-scheduler) can consume 1–2GB of RAM, which is a significant portion of available memory on ARM SBCs.

Additionally, full Kubernetes requires more manual configuration for a single-node or two-node setup and is harder to maintain without dedicated ops tooling.

## Decision

Use **k3s** as the Kubernetes distribution.

k3s is a CNCF-certified, lightweight Kubernetes distribution designed for resource-constrained environments. It ships as a single binary, replaces etcd with SQLite by default, and bundles Flannel (CNI), CoreDNS, and a local-path provisioner out of the box.

## Consequences

- Significantly lower memory footprint (~512MB for the server vs ~2GB for a full control plane)
- ARM64 is a first-class target — official k3s binaries are provided
- SQLite is sufficient for a small cluster; can be swapped for etcd later if the cluster grows
- Some advanced Kubernetes features are stripped or replaced (e.g. cloud-provider integrations) — acceptable for a homelab
- Directly relevant to thesis context: k3s represents the "lightweight container orchestration" end of the spectrum vs. hypervisor-based virtualization
